# Contributing to CrabER

## Naming

The product is **CrabER** — always that capitalization in prose, in the UI, in
docs, and in commit messages. Never "CraberER", "craber ER", "Craber", or
"CRABER". Everything machine-facing is lowercase `craber`:

| Where | Spelling |
|---|---|
| Prose, README, UI, docs | `CrabER` |
| Command, crate, package, repository | `craber` |
| Environment variables | `CRABER_` prefix |
| Config file | `craber.toml` |
| Docker image | `ghcr.io/<org>/craber` |
| Pronunciation | クラバー / "crab-er" |

## Getting set up

The repository ships a Nix flake. With `direnv` installed, `direnv allow` puts
Rust, Node, pnpm, `just` and `cargo-insta` on your PATH. Without Nix you need a
Rust toolchain (1.94 or newer — sqlx sets that floor), Node 24 and pnpm.

```console
$ just check       # fmt + clippy + tests. Run this before pushing.
$ just web-build   # typecheck and build the frontend
```

## Where things live

| Crate | Responsibility |
|---|---|
| `craber-core` | The schema IR, name resolution, filtering, diagnostics |
| `craber-parser` | SQL DDL → IR |
| `craber-introspect` | A live database → IR, via sqlx |
| `craber-layout` | IR → table positions |
| `craber-render` | IR + positions → SVG, with no browser in the loop |
| `craber-export` | The formats `--format` names, and the dispatch between them |
| `craber-site` | The static site `build` writes and `serve` hands out |
| `craber` | The CLI |

A new output format is taught to `craber-export` and nowhere else — the binary
asks it for bytes and does not know which crate produced them. The WASM crate is
added when its milestone comes up, rather than sitting empty.

## Two rules that are easy to break by accident

**`schema.json` is a public format.** The serde representation of the types in
`crates/craber-core/src/ir/` is what the static site, the single-file HTML and
the WASM demo all parse — including files generated by an older binary. Changing
a field name or type is a breaking change; bump `SCHEMA_VERSION` and say so in
the PR. The snapshot test in `crates/craber-core/tests/wire_format.rs` exists to
make sure that conversation happens.

**Never hand-edit `web/src/types`.** Those files are generated from the Rust
types by `ts-rs`. Edit `ir/`, run `just bindings`, and commit the result — CI
fails if the checked-in bindings are stale. (`index.ts` in that directory is the
one hand-written file; it is a barrel over the generated ones.)

## The frontend's gates

`tsc --noEmit` and `pnpm test` (`just web-test`). The tests cover the modules
that have no React in them — `diagram/graph.ts`, `diagram/anchors.ts`,
`schema.ts`, `sql.ts`, `viewState.ts` — and in particular the rules that are
stated once on each side of the language boundary: `endKinds` has to agree with
`End::referencing` in `crates/craber-render/src/edge.rs`, and `resolveRef` with
`SchemaIndex::resolve`. A disagreement there is not an error, it is one schema
drawn as two different diagrams.

Components are not unit-tested. Looking at the diagram in a browser is what
checks those, which is what `.claude/skills/ui-check` is for.

## Parsing is allowed to fail partially

Real schemas contain syntax CrabER does not handle. The parser returns an
`Outcome<Schema>` — a schema *plus* a list of `Diagnostic`s — rather than a
`Result`, so an unreadable statement produces a warning and a slightly
incomplete diagram instead of no diagram at all. When you add coverage for new
syntax, keep that shape: warn and continue, never bail.

## Commits and pull requests

Commit messages follow [Conventional Commits](https://www.conventionalcommits.org/):

```
feat(parser): read ALTER TABLE ADD CONSTRAINT FOREIGN KEY
fix(layout): stop overlapping nodes in single-column grids
docs: explain why layout runs in Rust
```

Scopes are the crate name without the `craber-` prefix (`core`, `parser`,
`introspect`, `layout`, `cli`, `web`). Explain *why* in the body; the diff already shows what.

## Cutting a release

Releases are built by cargo-dist from a pushed tag. The version lives
in nine places in `Cargo.toml` — `[workspace.package]` plus the eight path
dependencies, which `cargo publish` refuses without one — so never edit it by
hand:

```console
$ just bump 0.1.0   # cargo set-version --workspace; refuses to go backwards
$ just check
$ just publish-check    # rehearses the crates.io publish, uploading nothing
$ just nix-build        # the only check that the bundle really is in the binary
```

Then commit and tag. The tag has to be on `main`, and its version has to match
the manifest — dist derives the release from the tag, so a mismatch ships a
binary whose `--version` disagrees with its filename:

```console
$ git tag v0.1.0 && git push origin v0.1.0
```

Pull requests run the whole build matrix and attach the artifacts to the run
(`pr-run-mode = "upload"` in `dist-workspace.toml`), which is how to exercise the
pipeline without releasing. **Download one of those binaries and run
`craber build` against it.** A binary with no frontend compiled in still builds
and still installs; it only refuses at run time, and the Rust test for it passes
by skipping.

`.github/workflows/release.yml` is generated. Change `dist-workspace.toml` and
run `dist generate`; dist treats a hand edit as an error.
