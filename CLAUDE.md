# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

CrabER turns SQL DDL or a live database (PostgreSQL, MySQL, SQLite) into an ER diagram: SVG, JSON, an interactive viewer (`craber serve`), or a static site (`craber build`). It ships as one Rust binary with the React frontend compiled in. Pre-alpha.

The product is written **CrabER** in prose, UI, docs and commit messages; everything machine-facing (crate, command, `CRABER_` env vars, `craber.toml`) is lowercase `craber`.

## Commands

All tasks go through `just` (run `just` to list them). Toolchain: Rust 1.94+, Node 24, pnpm; `direnv allow` provides everything via the Nix flake.

```console
just check          # fmt-check + clippy (-D warnings) + cargo test --workspace — run before pushing
just check-all      # check + web-build + web-test
just web-build      # tsc --noEmit + vite build (runs `bindings` first)
just web-test       # vitest, pure TS modules only
just bindings       # cargo test -p craber-core → regenerates web/src/types and web/src/generated
just svg [file]     # render a schema to er.svg, quickest layout check
just demo [file]    # emit schema.json for a fixture
just ui [file]      # export into web/public/schema.json and start Vite; `just sample-reset` afterwards
just serve [file]   # run `craber serve`
just test-db        # #[ignore]d introspection tests against real PG/MySQL (needs Docker)
```

Single tests: `cargo test -p <crate> --test <file> <name>` (e.g. `cargo test -p craber-parser --test parse reads_columns`); `cd web && pnpm vitest run src/diagram/graph.test.ts`. Snapshot tests use `insta` (`cargo insta review` to accept changes).

## Architecture

Pipeline: **input → IR (`Schema`) → filter → layout → output**. `crates/craber/src/pipeline.rs::load` is the single path every command (`serve`, `build`, `export`) goes through, so they always show the same diagram.

- `craber-core` — the IR (`src/ir/`), name resolution (`SchemaIndex`), `Filter` (include/exclude/depth), `Diagnostic`/`Outcome`, theme/geometry constants, and codegen for the frontend.
- `craber-parser` (sqlparser) and `craber-introspect` (sqlx, sync API over a current-thread tokio runtime) both produce `Outcome<Schema>`.
- `craber-layout` — Sugiyama layout in Rust; positions are written into the `Schema`. The web app does not lay out tables, it reads positions from `schema.json`.
- `craber-render` — IR + positions → SVG, no browser.
- `craber-export` — owns every `--format`. A new output format is added here only; the CLI just asks it for bytes.
- `craber-site` — embeds `web/dist` at compile time via `build.rs` (or `bundle/` vendored by `just vendor-bundle`, or `CRABER_WEB_DIST`).
- `craber` — CLI (`cli.rs`, `options/` resolves flag > env > `craber.toml` > default), `commands/`, a small HTTP server in `server/`, `--watch` in `watch.rs`. `milestone.rs` names the milestone for not-yet-implemented commands/formats.
- `web/` — React 19 + React Flow (`@xyflow/react`) + Vite. Loads `schema.json`; view state lives in the URL (`viewState.ts`).

## Rules that are easy to break

- **`schema.json` is a public format.** The serde shape of `crates/craber-core/src/ir/` is parsed by the site and by files from older binaries. Renaming/retyping a field is breaking: bump `SCHEMA_VERSION` and say so in the PR. `crates/craber-core/tests/wire_format.rs` snapshots it.
- **Never hand-edit `web/src/types` or `web/src/generated`.** They are generated by ts-rs (`TS_RS_EXPORT_DIR` in `.cargo/config.toml`) and by craber-core tests. Edit Rust, run `just bindings`, commit the output — CI fails on a stale diff. `web/src/types/index.ts` is the one hand-written file.
- **Rules duplicated across the language boundary must agree:** `endKinds` (`web/src/diagram/graph.ts`) ↔ `End::referencing` in `crates/craber-render/src/edge.rs`; `resolveRef` (web `schema.ts`) ↔ `SchemaIndex::resolve`. A mismatch silently draws the same schema two ways.
- **Parsing fails partially.** Unsupported syntax yields a warning `Diagnostic` and the statement is skipped — warn and continue, never bail. Only error-severity diagnostics abort (`refuse_on_errors`).
- **Never put a DSN in an error or log message** — it carries a password and stderr ends up in CI logs.
- **The bundle is fail-soft.** Without `web/dist`, the Rust build only emits a `cargo:warning` and the binary refuses at run time; `crates/craber/tests/build.rs` passes by skipping. So `cargo build` must run *after* `just web-build` (`just dist`/`just install` do this). `just nix-build` is the only check that the bundle really landed in the binary.
- Workspace lints: `unsafe_code = "forbid"`, clippy `pedantic` as warnings (errors in CI).

## Frontend verification

Components are not unit-tested; vitest covers only the React-free modules (`diagram/graph.ts`, `diagram/anchors.ts`, `diagram/path.ts`, `schema.ts`, `sql.ts`, `viewState.ts`). A UI change is checked by looking at it in Chrome — use the `ui-check` skill (`.claude/skills/ui-check`): `just ui` → screenshot + console via claude-in-chrome → `just sample-reset`.

## Commits and releases

Conventional Commits; scope is the crate name without `craber-` (`core`, `parser`, `introspect`, `layout`, `render`, `export`, `site`, `cli`, `web`). Explain *why* in the body.

The version appears in nine places in `Cargo.toml`; change it only with `just bump <version>`. `.github/workflows/release.yml` is generated by cargo-dist — edit `dist-workspace.toml` and run `dist generate`. After changing `web/pnpm-lock.yaml`, run `just nix-pnpm-hash` to update the flake.
